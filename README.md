# 5주차 과제 1 — 하드코딩 설정 리팩터링
- 위험: 원본은 API 키·DB 비밀번호를 코드와 주석에 저장하고, DB URL과 요청 헤더 전체를 로그로 출력하여 코드 공유·로그·Git 이력으로 노출될 수 있었다.
- 수정: `python-dotenv`로 스크립트 옆 `.env`를 읽고, 하드코딩과 옛 키 주석 및 비밀 값 출력 로그를 제거했다. 필수 설정·월 형식과 모의 응답의 입출력도 검사한다.
- 설정: `.env.example`에는 설정 이름만 제공하고 키·DB 값은 비워 두었다. `.env`는 `.gitignore`로 제외했으며 필요한 패키지는 `requirements.txt`에 기록했다.
- 검증: 원본 `1ffc358`과 수정 `694ace4` 커밋이 있으며, 2026-09의 12건·106,000원 집계를 유지했다. [Git 검증 캡처](evidence/git_verification.png)에 status·check-ignore·ls-files 결과가 있다.
- 본 과제의 키·DB 비밀번호는 권한이 없는 교육용 더미이며 외부 API·실제 DB에 접속하지 않는다. 아래는 실제 키가 노출됐다고 가정했을 때의 대응이다.
- ① 노출된 키를 즉시 폐기(revoke)하고 새 키를 재발급한다. DB 접속 비밀번호가 노출됐다면 해당 자격증명도 변경한다.
- ② 새 키를 `.env`로 분리하고 `.gitignore`를 정비하여 Git 추적에서 제외한다.
- ③ 사용량·청구 내역을 점검하고 필요하면 서비스 사업자에게 신고한다.
- ④ 키 무효화 후 필요하면 이력 재작성 도구로 저장소를 정리한다. 현재 코드에서 줄을 삭제하고 다시 커밋하는 것만으로는 과거 이력의 키가 사라지거나 무효화되지 않는다.
